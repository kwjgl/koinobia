# 코이노비아 브랜드 가이드라인

- 버전: 1.3
- 정리일: 2026-11-18
- 용도: 홈페이지·앱 소개·인스타그램·교재·문구·홍보물 등의 언어 및 시각 제작 기준
- 상위 기준: [브랜드 전략서](brand-strategy.md)

> 이 문서는 브랜드의 표현을 일관되게 하기 위한 기준이다. 아래의 색상·서체 값은 2026-11-18 현재 코이노비아 사이트 구현을 기준으로 기록했다. 기존 사이트를 즉시 수정하라는 지시가 아니다.
>
> 이 문서는 추후 비공개 관리 저장소(`koinobia.admin`)로 옮길 예정이다.

## 1. 표현의 중심

**대표 문장**

> 오래된 신앙의 실천을 오늘의 삶으로 이어 갑니다.

**짧은 소개**

> 코이노비아는 함께 신앙의 길을 걷는 사람들을 위해 도구를 만드는 독립 스튜디오입니다. 기도와 말씀과 자람의 실천을 돕는 앱과 교재를 만듭니다.

**브랜드를 설명할 때**

- 오래된 신앙의 실천을 존중한다는 관점부터 말한다.
- 어떤 문제를 해결하는지와 실제 기능을 구체적으로 쓴다.
- 혼자가 아니라 공동체와 함께하는 신앙이라는 점을 놓치지 않는다.
- 앱이든 책이든 도구가 신앙 자체를 대신하거나 신앙의 깊이를 측정한다고 말하지 않는다.
- 준비 중이거나 기획 중인 제품은 ‘준비 중’이라고 분명히 밝힌다.
- ‘독립출판사 같은’ 인상은 글의 양식보다 관점과 편집의 태도로 보여 준다.

## 2. 언어 정체성

### 기본 톤

담백하고 정확하며, 읽기 쉬운 문장. 친절하되 지나치게 다정한 척하지 않는다. 신학적 입장은 분명하게 말하되 독자에게 훈계하지 않는다.

- **브랜드 스테이트먼트·공식 소개:** 간결한 합쇼체를 기본으로 한다.
- **앱 안내·도움말:** 사용자가 이해하기 쉬운 존댓말을 쓴다. 기존 화면의 말투는 개별 수정 작업에서 조정한다.
- **개발 노트:** 무엇을 고민하고 어떤 선택을 했는지 구체적으로 기록한다. 기능의 결과만 홍보하지 않는다.
- **인스타그램:** 짧은 문장과 충분한 여백을 사용하되 내용을 희생하면서까지 시적으로 꾸미지 않는다.
- **교재:** 학습자가 혼자서도, 모임에서도 따라갈 수 있게 쉽고 정확하게 쓴다. 성경 인용과 신학적 출처를 밝히고, 리더용 지도서에는 진행 의도와 질문의 목적을 함께 적는다.

### 피할 표현

다음 표현이 금지되는 것은 아니다. 다만 뜻을 더하지 않으면서 분위기만 내려고 반복하지 않는다.

- ‘깃들다’, ‘머물다’, ‘작은 자리’, ‘조용히’, ‘일상을 가꾸다’ 같은 관습적인 감성 어휘 — 구체적인 뜻이 있을 때만 쓴다
- ‘혁신적인’, ‘완벽한’, ‘최고의’, ‘새로운 신앙 경험’ 같은 과장
- 사용자의 경건이나 성장을 성적·경쟁·성과로 바꾸는 표현
- 제품의 실제 기능보다 큰 약속을 하는 문구

| 피하는 방향 | 권하는 방향 |
| --- | --- |
| 기도 습관을 혁신적으로 관리하세요. | 기도제목을 기록하고 필요한 사람들과 나눌 수 있습니다. |
| 말씀의 깊은 울림이 일상에 깃듭니다. | 말씀을 읽으며 떠오른 질문을 기록하고 함께 나눕니다. |
| 세 가지 서비스가 당신을 완성합니다. | 코이데는 기도를 돕고, 디다코(준비 중)와 텔리오(기획 중)는 말씀과 자람을 돕습니다. |
| 신앙 생활 필수템, 코이노비아 굿즈 | 소그룹에서 기도제목을 적고 나누는 카드입니다. |

## 3. 시각 정체성

### 기본 원칙

독립출판물처럼 **내용과 조판이 우선하는 편집 디자인**을 지향한다. 화면마다 같은 배경색이나 장식을 반복하지 않는다. 대신 여백, 서체의 위계, 색 사용의 일관성으로 브랜드를 연결한다.

- 한 화면의 주제는 가능한 한 하나로 정한다.
- 제목과 본문, 설명 사이에 충분한 공간을 둔다.
- 장식용 작은 글이나 의미 없는 영문 레이블을 습관적으로 넣지 않는다.
- 실제 앱 화면을 보여 주는 콘텐츠는 가짜 UI 이미지보다 스크린샷을 우선한다.
- 사진, 일러스트, 타이포그래피 게시물은 각기 다른 형식을 쓸 수 있다.

### 색상 — 현재 사이트 기준

코이노비아는 흰색·먹색을 중심으로 하고, 각 앱의 색을 구별해서 쓴다. 아래 값은 `index.html` 및 `page.css`의 CSS 변수에서 가져온 **라이트 모드 현재값**이다.

| 용도 | CSS 변수 | 값 |
| --- | --- | --- |
| 기본 바탕 | `--page` | `#FFFFFF` |
| 보조 바탕 | `--surface-2` | `#F4F4F1` |
| 본문 먹색 | `--ink` | `#1D1D1B` |
| 코이데(초록) | `--c0` | `#2B6A62` |
| 디다코(갈색) | `--c1` | `#6B4A2E` |
| 텔리오(장미색) | `--c2` | `#A8435C` |

인쇄물에서는 위 값을 그대로 쓰지 않는다. 화면색(RGB)과 인쇄색(CMYK)은 다르게 나오므로, 인쇄용 색상값은 시험 인쇄(교정쇄)로 확인한 뒤 이 문서에 별도로 기록한다.

다크 모드 값은 별도로 정의되어 있으므로 코드를 작업할 때는 기존 CSS 변수를 참조한다. 위 색상을 독립된 새 하드코딩 값으로 여러 군데 복제하지 않는다.

앱 색이 아닌 중립적인 코이노비아 콘텐츠는 먹색·흰색·미색의 조합을 먼저 고려한다. 색을 세 가지 모두 한 화면에 넣어야 하는 것은 아니다.

### 서체 — 현재 사이트 기준

- 제목 계열: **Gowun Batang** (고운바탕), `--f-display`
- 본문 계열: **IBM Plex Sans KR**, `--f-body`
- 대체 서체: 사이트 CSS의 폴백 체인을 따른다.

제목과 본문은 무게·크기·간격으로 위계를 만든다. 한 게시물에 여러 서체를 추가해 분위기를 만드는 방식은 지양한다. 두 서체는 SIL 오픈 폰트 라이선스(OFL)로 배포되어 인쇄물에도 쓸 수 있다. 다만 교재 본문처럼 긴 글에는 본문용 서체를 따로 검토할 수 있으며, 다른 서체를 쓸 때는 사용 권한과 한글 가독성을 확인하고 결정한다.

### 로고와 상징

코이노비아 로고는 **매듭 심볼**과 **영문 워드마크 KOINOBIA**로 이루어진다. (2026-11-18 확정)

**매듭 심볼**은 **끊기지 않는 한 줄로 엮인 세 고리**다. 기도·말씀·자람의 세 실천과 세 제품군의 연결을 나타낸다. [이야기](../about/index.html)에서 설명한 삼위일체 신앙에 관한 고백도 존중한다. 다만 로고를 하나님 자체를 묘사한 형상처럼 다루지 않는다.

**워드마크**는 대문자 KOINOBIA다. 대문자로 쓰면 영어이면서 그리스어(ΚΟΙΝΟΒΙΑ)로도 읽혀, 이름의 뿌리인 ‘코이노비온’을 드러낸다.

- 바탕 서체: Tenor Sans(SIL 오픈 폰트 라이선스). 로고 파일은 글자를 윤곽선으로 바꿔 두었으므로 서체 없이도 같은 모양으로 보인다.
- 두 개의 O는 매듭의 고리와 같은 **정원**으로 바꿨다. 심볼이 없는 자리에서도 매듭을 떠올리게 하는 장치다.
- A는 **가로획을 뺐다**(Λ). 고대 그리스 비문의 글자꼴과 닮았다.
- 자간은 0.11em, 획은 서체 원래 두께보다 조금 굵게(+0.014em) 했다.

#### 사용 원칙

- 심볼은 **언제나 워드마크 앞(왼쪽)**에 둔다. 크기는 워드마크 대문자 높이의 약 1.2배이며, 로고 파일의 비율을 그대로 쓴다.
- 한글 ‘코이노비아’는 로고에 붙이지 않는다. 작은 크기에서 점처럼 뭉개지기 때문이다. 한글 이름은 로고 옆 본문이나 소개 문장에서 보통 글자 크기로 쓴다.
- 로고 파일을 다시 그리거나, 늘이거나, 다른 서체로 바꾸지 않는다. 고리 O와 Λ를 일반 O·A로 되돌리지 않는다.
- 로고 둘레에는 최소한 워드마크 대문자 높이의 절반만큼 여백을 둔다.
- 워드마크는 높이 12px(인쇄 4mm) 아래로 줄이지 않는다. 더 작은 자리에는 심볼만 쓴다.
- 색은 먹색(#1D1D1B) 또는 밝은 먹색(#ECECE8)만 쓴다. 앱 색으로 칠하지 않는다.
- 개별 제품군(앱·교재·종이 도구)을 소개할 때는 각 제품군의 고유 로고·색을 쓰고, 코이노비아 로고는 작게 함께 둔다.

#### 앱 시작 화면 (2026-11-18 적용)

코이데·디다코는 앱을 켤 때의 시작 화면에서 코이노비아를 "만든 곳"으로 조용히 알린다. 화면의 주인공은 앱 이름이다.

- **어디에:** 앱을 새로 켤 때 나오는 시작 화면에만 둔다. 노트·공동체·교회·모임·관리 사이를 오가는 **전환 화면에는 두지 않는다.** 오갈 때마다 뜨는 화면에 로고가 반복되면 광고처럼 느껴지고, 그 화면은 가는 곳을 알리는 데 집중해야 하기 때문이다.
- **자리:** 화면 맨 아래 가운데, 안전 영역(홈 막대) 위 40px. 높이가 420px 이하인 화면(가로로 눕힌 휴대폰)에서는 앱 이름과 겹치지 않게 숨긴다.
- **구성과 크기:** 심볼 + 워드마크. 심볼 18px, 워드마크 높이 11px, 사이 7px.
- **색:** 앱의 보조 글자색(`--ink-2`) 한 가지. 매듭의 세 고리는 같은 색의 진하기만 달리한다(100% · 78% · 56%). 앱의 밝은·어두운 화면과 색 테마를 그대로 따른다. 먹 세 톤이나 앱 색으로 칠하지 않는다.
- **움직임:** 앱 이름보다 조금 늦게 살짝 올라오며 나타난다. 움직임 줄이기 설정에서는 움직이지 않는다.
- **누를 수 없다.** 앱 안에 바깥 링크나 후원 버튼을 두지 않는다는 원칙에 맞춘다.
- **한글 이름이나 "from" 같은 글은 붙이지 않는다.** 로고만 둔다.
- **로고가 바뀌면:** 로고 그림은 이 저장소의 확정 로고(`tabs.js`의 LOGO·WORDMARK)를 각 앱의 시작 화면 파일에 옮겨 쓴다(코이데 `pray-for/app/splash.js`, 디다코 `gbs/note/splash.js`). 로고를 바꾸면 두 앱도 함께 바꾼다.
- 새 앱(텔리오 등)을 만들 때도 같은 규칙을 따른다.

### 사진과 이미지

실제 책·종이·손글씨·생활의 장면처럼 주제와 연결되는 이미지가 어울린다. 다만 ‘감성적인 스톡 사진’ 자체가 목표는 아니다.

- 내용과 관련 없는 장식 이미지, 과한 필터, 인공적인 질감은 피한다.
- 실제 앱 기능을 설명할 때는 실제 화면을 사용한다.
- AI 생성 이미지를 쓴다면 실제 앱 화면이나 현장 사진처럼 오해받지 않게 한다.
- 인물·저작물·외부 이미지는 사용 권한을 확인한다.

## 4. 매체별 적용

| 매체 | 우선할 것 | 주의할 것 |
| --- | --- | --- |
| 홈페이지 ‘이야기’ | 브랜드를 만든 이유, 신학적 관점, 세 앱의 연결 | 브랜드 문구만 반복하지 않기 |
| 앱 소개 | 실제 사용 상황과 기능, 이용 범위 | 추상적인 브랜드 문장만 늘어놓지 않기 |
| 개발 노트 | 선택의 배경, 대안, 결정과 한계 | 모든 결정을 ‘브랜드 철학’으로 포장하지 않기 |
| 인스타그램 | 게시물 하나에 주제 하나, 여백과 조판, 시리즈별 변주 | 모든 콘텐츠를 똑같은 카드 틀에 넣지 않기 |
| 교재 | 학습 목표, 성경 본문, 질문의 흐름, 모임에서 쓰기 쉬운 지면 | 앱 사용을 전제로 하지 않기. 종이만으로도 공부가 되게 하기 |
| 문구·종이 도구 | 실제 기도·말씀·자람의 실천에 쓰이는 구성 | 로고만 얹은 굿즈 만들지 않기. 신앙 물품처럼 오해받지 않게 하기 |
| 후원·교회용 안내 | 비용, 이용 대상, 제공 범위의 투명성 | 후원이나 구독, 구매를 신앙적 의무처럼 말하지 않기 |

## 5. 게시·제작 전 확인

1. 실제 제품의 기능이나 현재 제공 범위를 정확히 설명하는가? 준비 중인 제품을 밝혔는가?
2. 브랜드의 핵심 문장과 핵심 가치에 어긋나지 않는가?
